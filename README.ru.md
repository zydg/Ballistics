# 弹道学 · Ballistics

Клиентский плагин BepInEx 5 для SPT, который визуализирует то, что игра считает сама:
траектории пуль с окраской по реальной остаточной пробиваемости и урону, зоны поражения
взрыва, кольца оглушения, траектории твёрдых тел (граната / фальшфейер) и предпросмотр
броска гранаты, повторяющий ванильную математику. Только клиент — без серверной
части, данные игры не изменяются.

- Совместимость: SPT 4.1.6 (EFT 0.16.9.40743), BepInEx 5.4.23.5, HarmonyX
- Имя плагина: `zydg666-Ballistics` · GUID `com.zydg666.ballistics`
- Необязательно: BepInEx.ConfigurationManager (образцы цвета в интерфейсе настроек)
- Языки: по умолчанию **Auto** (язык системы, иначе английский), плюс English, 简体中文 и Русский (`Lang/*.json`), выбор в `General → Language`

## Честная игра

> **Функции предсказания могут влиять на баланс игры.** `Prediction → GrenadeArc`, `TrajectoryPreview`,
> `BlastPreview`, `PreviewInner` и `PreviewStun` показывают информацию, которую игра обычно не выводит
> на экран (куда упадёт граната, как пойдёт траектория оружия в руках, где рванёт летящая граната).
> **Все они по умолчанию выключены**; включайте их в разделе `Prediction`, если они вам нужны, и решите
> сами, допустимо ли это на вашем сервере или в сообществе.

> **Совместимость.** Проверено с более чем 100 модами сообщества, установленными одновременно;
> несовместимостей не обнаружено. Если конфликт всё же возникнет, напишите об этом.

> **Сделано с помощью ИИ.** Код и документация написаны с участием ИИ-ассистента. Если заметите
> ошибку, несогласованность или пропуск — напишите об этом.

Остальные функции (запись уже сделанных выстрелов, реальные радиусы после взрыва, статистика
попаданий) лишь воспроизводят то, что игра уже посчитала, и не дают преимущества до выстрела.

## Установка

1. Закройте игру.
2. Распакуйте архив в корень игры (рядом с `EscapeFromTarkov.exe`), чтобы получилось:

   ```
   BepInEx/plugins/Ballistics/Ballistics.dll
   BepInEx/plugins/Ballistics/Lang/zh.json
   BepInEx/plugins/Ballistics/Lang/ru.json
   ```

3. Запустите игру. Конфиг появится в `BepInEx/config/com.zydg666.ballistics.cfg`.

Удаление: удалите `BepInEx/plugins/Ballistics` (по желанию — конфиг и `BepInEx/config/Ballistics`).

## Язык

`General → Language` принимает `Auto` (по умолчанию), `English`, `简体中文`, `Русский`.

- **`Auto` по умолчанию**: следует языку интерфейса системы (zh → 简体中文, ru → Русский);
- нераспознанный язык откатывается к английскому, включая случай отсутствующей папки `Lang`;
- английские строки встроены в DLL; остальные читаются из
  `BepInEx/plugins/Ballistics/Lang/<code>.json` (плоская карта `{"ключ":"текст"}`), отсутствующие
  ключи откатываются к английскому, затем к имени ключа;
- смена языка влияет только на **новые** тексты; панель и подписи в конфиге переключаются сразу,
  а описания настроек требуют перезапуска игры.

## Конфигурация

Конфиг создаётся в `BepInEx/config/com.zydg666.ballistics.cfg`. Разделы: `General`,
`Trajectory`, `Explosives`, `Prediction`, `Debug`; ключи — стабильные ASCII-идентификаторы,
а тексты описаний следуют выбранному языку.

**General**

|---|---|---|
| `Language` | `Auto` | Язык интерфейса: Auto / English / 简体中文 / Русский. Панель переключается сразу; описания в конфиге — после перезапуска. |
| `Enabled` | `true` | Главный выключатель: при выключении ничего не рисуется. |

## Как считается (как в ванильной игре)

| Шаг | Источник |
|---|---|
| Сэмплирование | Последняя запись `Shot.PositionHistory` после `Shot.UpdateBulletPosition` |
| Завершение | `HittedBallisticCollider != null` или превышение `AmmoLifeTime` |
| Точка попадания | `Shot.HitPoint` (`_hit.point`), конец линии привязан к отверстию |
| Признак пробития | Собственный сигнал остановки игры (`BlockedBy` / `DeflectedBy` / `IsShotFinished`); если та же цепочка попадает снова, предыдущая точка считается пробитой |
| Окраска | `DamageInfo.PenetrationPower` / `Damage` при попадании ÷ начальное значение патрона → ступенчатая шкала |
| Дочерние пули | Регистрируются патчем `Shot.Create`, значения берутся у самой дочерней пули |

Радиусы взрыва рисуются только при ванильных условиях: `MaxExplosionDistance > 0.1`,
`FragmentIndex == 0`, `IsFirstHit`, `TimeSinceShot >= FuzeArmTimeSec`.

Дуга гранаты: точка вылета, направление и начальная скорость измерены на ванильном броске
(импульс: Δv = force / mass); скорость игрока складывается, начало сдвигается на измеренную
задержку 0.475 с.

## Известные ограничения

- Ванильное направление броска содержит случайный член `Random.onUnitSphere × (0.5 − выносливость)` (до ±5.7°), поэтому точную точку падения предсказать нельзя.
- Пробитие тонких материалов (стекло, тонкий металл) отнимает меньше 1% остатка — отсутствие смены цвета на ступенчатой шкале корректно.
- Живой предпросмотр радиуса взрыва может отставать от записанного до 0.25 м (троттлинг обновления).
- Для фальшфейеров записывается только траектория полёта, без взрыва.

## Структура разработки

Один и тот же код даёт две сборки, переключаются через `build.ps1 -Config`:

- **Release (фиксированная оболочка, для распространения)**: `Loader.cs + Impl.cs + Lang.cs + LangEn.g.cs + Version.cs`
  собираются с `/define:STATIC_BUILD` в **единственный `Ballistics.dll`**; вся логика внутри, во время
  работы внешние сборки не загружаются.
- **Debug (оболочка + горячая перезагрузка, для разработки)**: две части — `Ballistics.dll` только
  оболочка (точка входа, конфиг, панель), а `Impl.cs` отдельно компилируется в
  `BepInEx/plugins/Ballistics/Impl/BallisticsImpl.bytes`; оболочка загружает его через
  `Assembly.Load(bytes)` при старте и по `Debug → ReloadKey`, предварительно вызывая `Config.Reload()`
  и `UnpatchSelf()`, поэтому после правок игру перезапускать не нужно.

`LangEn.g.cs` генерируется из `lang/en.json` при сборке (поэтому английский встроен в DLL);
`Lang/zh.json` и `Lang/ru.json` читаются во время работы, им нужна только перезагрузка.

Файлы:

- `Loader.cs` — оболочка: точка входа `BaseUnityPlugin`, привязка `General.Language` и настроек панели
  в `Debug`, обе ветки загрузки (статическая и горячая), `ShellHost` (`Update` вызывает тик
  реализации, `OnGUI` рисует панель).
- `Impl.cs` — реализация: все патчи Harmony (`Shot.Create`, `UpdateBulletPosition`, `HandleCollision`,
  деградация пробиваемости, дочерние пули, граната и взрыв, отслеживание твёрдых тел, определение
  локального игрока), запись и окраска трасс, текст панели, остальные настройки.
- `Lang.cs` — определение языка (Auto → культура системы → английский) и чтение плоского JSON.
- `lang/*.json` — переводы; `en.json` единственный источник английского, из него генерируется `LangEn.g.cs`.
- `build.ps1` — генерирует `Version.cs` / `LangEn.g.cs`, собирает, ставит и упаковывает по `-Config`.
